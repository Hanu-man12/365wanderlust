## Executive Summary

**365 Wanderlust** is a static, single-page React/Vite marketing website for a Rajasthan travel company branded **"Grab Your Leisure"**. It has no backend — all contact/enquiry goes through WhatsApp via `wa.me` links. The site is production-ready in terms of code quality but is **content-incomplete**: several fields in `siteData.js` are placeholders awaiting owner input, and all images are "trial" posters awaiting final photography.

The live domain is `365wanderlust.com`. The business is a Rajasthan-focused travel planning company targeting domestic and international leisure travellers.

## 6. Component Roles

### `Navbar.jsx`
Fixed sticky header. At top: fully transparent. On scroll: glassmorphism (white frosted glass in light mode, dark glass in dark mode). Uses `IntersectionObserver` to highlight the active section. Includes mobile hamburger with focus trap and Escape key support. Active section tracked via `IntersectionObserver` across `#home`, `#about`, `#destinations`, `#contact`. Logo pulls from `brand.logo` and `brand.name` in siteData.

### `Hero.jsx`
Full-viewport hero section with a two-layout strategy: **mobile** (≤640px) = flow layout (image in DOM, height = image height, no gap), **desktop** (>640px) = viewport-fill with `object-fit: cover`. The hero image is the branded `hero-banner.jpeg` which has text baked into it ("GrabYourLeisure" collage). CTA button scrolls to `#contact`.

### `About.jsx`
Editorial text-only section (`#about`). No photo — three paragraphs of company description on `off-white` background. Paragraph 1 is hardcoded in the component (`PARAGRAPHS` array), not from siteData. Decorative SVG mandala ornament (top-right, 5% opacity). **Note:** `About.jsx` ignores the `about` export from siteData — it uses a local `PARAGRAPHS` constant with the actual company copy.

### `Destinations.jsx`
Staggered alternating grid of 5 destination cards (`#destinations`). Each card: polaroid `FramedImage` + destination name, subtitle (Dancing Script font), description, highlight tags, WhatsApp enquiry CTA. Clicking a framed image opens a `Lightbox`. Layout flips image/text side alternately (even/odd index). Collapses to single column on mobile.

### `WhyChooseUs.jsx`
Animated horizontal carousel on crimson-red background (`#why-choose-us`). 6 cards with glass morphism styling (semi-transparent white) scroll continuously in a sine wave pattern using `requestAnimationFrame`. Duplicates cards for seamless infinite scroll. Pauses on hover/touch. Respects `prefers-reduced-motion`. Background: panoramic world landmark SVG served from `/public/landmark-skyline.svg`. Supports touch swipe.

### `Contact.jsx`
Two-column layout: EnquiryForm (right on desktop, first on mobile) + contact info column (left on desktop). Contact info shows phone (with copy button), email (with copy button), social links (Instagram, Facebook, YouTube). Uses `flex-row-reverse` trick so DOM order matches mobile reading order while visually showing info on left on desktop. Background: parchment texture.

### `Footer.jsx`
Three-column dark footer: brand column (logo + tagline + description + social icons), Quick Links nav, Contact info (phones + email + domain). Copyright line with dynamic year. Collapses to single column on mobile. Uses `bg-ink` (near-black). Social WhatsApp icon in footer links to `#contact` section, not directly to WhatsApp.

### `EnquiryForm.jsx`
WhatsApp-based enquiry form. Fields: Name* (required), Phone* (required), Email (optional), Destination (dropdown from siteData destinations), Travel Dates From/To (native `<input type="date">` with today as min), No. of Travellers (dropdown), Message. On submit: validates name + phone, composes formatted WhatsApp message, opens `wa.me` link in new tab. No data stored — purely client-side. Shows confirmation state after submit.

### `Preloader.jsx`
Branded loading animation shown once per browser session (via `sessionStorage`). Phases: counting (0→100 counter tied to `window load` event + MIN_DISPLAY=2400ms) → disassembling (letters scatter) → logoFading → sliding (crimson door wipe) → done. Uses `motion/react` for animations. Respects `prefers-reduced-motion` (simple fade fallback). Locks scroll during display.

### `ThemeToggle.jsx`
Floating circular button (bottom-right, `position: fixed`). Shows Moon icon in light mode, Sun icon in dark mode. Toggles `dark` class on `<html>` and persists choice to `localStorage` under key `365w-theme`. Appears only after scrolling 300px. Anti-flash: `index.html` contains an inline script that reads `localStorage` before React mounts.

### `Lightbox.jsx`
Custom lightweight image viewer. Supports: keyboard Esc (close), ← → (navigate), click-outside-to-close, touch swipe navigation. Accessible: `role="dialog"`, `aria-modal`, focus trap, close button gets initial focus. Can operate in single-image mode or multi-image array mode with prev/next navigation.

### `FramedImage.jsx`
Reusable polaroid/postcard style image frame. White background, bottom padding for caption area, slight box shadow, hover lifts and straightens. CSS class `framed-image` defined in `index.css`. Accepts `rotation` prop (CSS transform). Clickable if `onOpen` callback provided. `object-fit: contain` — never crops.

### `Reveal.jsx`
Scroll-reveal wrapper using `IntersectionObserver` (threshold: 0.12). Adds CSS class `visible` when element enters viewport (one-shot). CSS in `index.css` defines the `reveal` → `reveal.visible` transition (opacity 0→1, translateY 28px→0, 0.7s ease). Delay classes `reveal-delay-1` through `reveal-delay-4` add stagger.

### `SectionHeading.jsx`
Reusable `<h2>` block with optional label (uppercase small-caps), ornamental compass SVG divider, and subtext. Supports `align` (center/left) and `theme` (light/dark) props. Dark mode overrides handled via `html.dark` CSS rules embedded in the component.

### `Gallery.jsx` *(not currently rendered)*
Editorial asymmetric gallery with 5 framed images. Varied sizes (large/medium/small), staggered vertical offsets for masonry feel. Lightbox support. Dark ink background. Currently commented out / removed from `App.jsx`.

### `Packages.jsx` *(not currently rendered)*
Cards for 2 travel packages with expandable day-by-day itinerary (accordion). Shows featured badge, price (or "Price on Request"), WhatsApp CTA per package. Placeholder content in package 2 (Royal Rajasthan Tour).

### `Journey.jsx` *(not currently rendered)*
Three-chapter storytelling section with alternating framed image + text layout. Decorative vertical timeline line. Script accent "Until the next journey..." on the last chapter.

### `WhatsAppFloat.jsx` *(not currently rendered)*
Green floating WhatsApp button (appears after 300px scroll). Currently replaced in position by `ThemeToggle.jsx`. Both would conflict on the same `bottom: 2rem, right: 1.5rem` position if both rendered.

## 7. Styling Approach

- **Tailwind CSS v4** via Vite plugin — loaded as `@import "tailwindcss"` in `index.css`
- **Custom design tokens** in `@theme {}` block in `index.css` — these become CSS custom properties (`--color-brand-red`, `--font-serif`, etc.) used throughout components via inline `style` props
- **Primary color palette:** Crimson `#D0112B`, White `#FFFFFF`, Near-black `#0D0D0D`
- **Typography stack:** Cormorant Garamond (headings/serif), DM Sans (body), Dancing Script (script/accent), Montserrat ExtraBold Italic (brand wordmark only)
- **Dark mode:** `html.dark` class toggled by ThemeToggle; CSS custom properties redefined under `html.dark {}` in `index.css`; extensive component-level dark overrides also in `index.css`
- **Animation:** CSS transitions for hover states; CSS `@keyframes` for scroll bounce; `IntersectionObserver` + CSS class for scroll reveals; `motion/react` for Preloader animation only; `requestAnimationFrame` for WhyChooseUs carousel
- **Inline styles vs CSS classes:** Components overwhelmingly use inline `style` props with `var(--token)` references. CSS classes used for responsive breakpoints (media queries in `<style>` tags within components) and shared utilities (`.reveal`, `.framed-image`, `.bg-ink`, etc.)

## 10. Key Issues & Recommendations

### Content gaps (owner action required)
1. `about.storyParagraph1` in siteData is `[ADD COMPANY STORY...]` — hardcoded placeholder
2. `contact.address` is `[ADD YOUR OFFICE / CITY ADDRESS HERE]`
3. `packages[1]` (Royal Rajasthan Tour) — duration, description, and all highlights are placeholders
4. `packages[0]` Days 1 & 2 itinerary are placeholder
5. `contact.social.youtube` is empty
6. All images in `src/assets/trial/` are poster-style marketing images, not real photography
7. `hero.heroImage` points to a collage banner with baked-in text — no real hero background photo yet
8. OG image `/public/og-image.jpg` missing (social share preview will be broken)
9. Favicon is `public/favicon.png` — appears to be set but should be checked

### Dead code / unused components
- `Gallery.jsx`, `Packages.jsx`, `Journey.jsx`, `WhatsAppFloat.jsx` are all built but **not rendered**
- `App.jsx` comment says "Packages and Journey sections have been removed" — the intention is clear, but these files should either be re-integrated or removed to avoid confusion
- Note: `Gallery` and `WhatsAppFloat` are also removed despite having no comment explaining why

### About component ignores siteData
- `About.jsx` defines a local `PARAGRAPHS = [...]` constant with hardcoded copy
- It does not use `about.storyParagraph1` / `about.storyParagraph2` from siteData
- This breaks the "change content in siteData only" promise in the README
- Recommendation: either use the siteData `about` fields in `About.jsx`, or remove the redundant `about` export from siteData

### WhatsApp number in siteData vs README discrepancy
- `siteData.js` has `whatsappNumber: '917605809599'`
- `README.md` examples still show `917425010750` as the example number to change
- The README is outdated but this is minor

### `About.jsx` hardcodes copy instead of using siteData
- Three paragraphs in `About.jsx` are hardcoded strings, not pulled from `siteData.about`
- This is inconsistent with the rest of the site architecture

### ThemeToggle and WhatsAppFloat position conflict
- Both use `bottom: '2rem', right: '1.5rem'`
- ThemeToggle is rendered; WhatsAppFloat is not — but if WhatsAppFloat is re-added they will overlap
- Recommendation: offset one of them (e.g. WhatsAppFloat at `bottom: 5.5rem`) if both are rendered

### No analytics
- There is no analytics integration
- For a travel marketing site this is a notable gap — recommend adding Vercel Analytics (zero-config) or Plausible

### Missing public assets
- `/public/og-image.jpg` — missing, social share preview will use no image
- Favicon appears present (`public/favicon.png` listed) but should be verified as correct brand icon

### `index.html` title tag
- `<title>Grab Your Leisure</title>` — does not include the brand name "365 Wanderlust"
- Better: `<title>365 Wanderlust — Grab Your Leisure</title>` (matches `seo.title` in siteData but index.html is not using that value)
